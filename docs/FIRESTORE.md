## Назначение

Этот документ фиксирует модель данных Firestore на уровне домена.

Исполняемой спецификацией являются файлы конфигурации и правила в `infrastructure/firebase/`. Приоритет у них.

---

## Ключевые коллекции

В текущей реализации приложение использует небольшое число корневых коллекций и несколько подколлекций. Часть данных хранится прямо в документе, а не отдельной коллекцией.

<div align="center">

| **Путь** | **Назначение** |
|:---|:---|
| `users` | Профили пользователей, приватность, FCM токены, counters и массивы интересов/друзей |
| `users/{uid}/notifications` | Уведомления конкретного пользователя |
| `communities` | Сообщества по интересам |
| `events` | События, участники, настройки доступа и метаданные |
| `events/{eventId}/reviews` | Отзывы на события |
| `events/{eventId}/applications` | Заявки на участие в событиях |
| `chats` | Диалоги между пользователями |
| `chats/{chatId}/messages` | Сообщения чата |
| `interests` | Глобальный справочник интересов |
| `reports` | Жалобы и модерационные обращения |

</div>

### Что лежит в документе

- `users` хранит профиль пользователя (`username`, `displayName`, `photoUrl`, `bio`, `age`, `privacyLevel`, координаты, `friends`, `interests`, `fcmTokens` и счетчики активности).
- `communities` хранит описание сообщества, список `members`, `moderators`, `privacyLevel`, `minAge`, `maxMembers` и `requiresApproval`.
- `events` хранит событие целиком: `organizerId`, `participants`, `coOrganizers`, `categories`, `visibility`, `eventType`, координаты, статус и метаданные.
- `chats` хранит пару участников, последнее сообщение и время последней активности; сообщения лежат в подколлекции `messages`.
- `events/{eventId}/reviews` содержит отзыв с `authorId` / `userId`, `rating`, `comment`, `createdAt`.
- `events/{eventId}/applications` содержит статус заявки (`pending`, `approved`, `rejected`).

## Правила безопасности

<div align="center">

| **Данные** | **Чтение** | **Запись** |
|:---|:---|:---|
| `users` | По уровню приватности профиля | Только владелец документа |
| `users/{uid}/notifications` | Только владелец | Только системные операции |
| `communities` | Публичные — всем, приватные — участникам | Только создатель / участник с правами |
| `events` | Публичные — всем, приватные — организатору и участникам | Организатор, модератор или системный процесс по правилам |
| `events/{eventId}/reviews` | Всем или участникам события, в зависимости от правил | Только подтверждённый участник |
| `events/{eventId}/applications` | Организатору и заявителю | Заявитель создаёт, организатор меняет статус |
| `interests` | Всем | Только администратор |
| `chats` | Только участникам чата | Только участникам чата |
| `chats/{chatId}/messages` | Только участникам чата | Только участникам чата |
| `reports` | Автору жалобы и администраторам | Создание автором, изменение модератором |

</div>

## Конфигурация и индексы

<div align="center">

| **Параметр** | **Значение / правило** |
|:---|:---|
| Путь к правилам доступа | `infrastructure/firebase/firestore.rules` |
| Путь к индексам | `infrastructure/firebase/firestore.indexes.json` |
| Единица изменения | Одно изменение схемы/запроса = один PR с обновлением правил или индексов |
| Изменяемость | Правила и индексы изменяются только через ревью и согласованный PR |

</div>

---

## Правила изменений схемы

- добавление новых полей должно быть обратно совместимым;
- изменение уровней приватности и ролей согласуется с Security Rules;
- новые составные запросы требуют соответствующего индекса в `firestore.indexes.json`;
- изменения доступа в `firestore.rules` и `storage.rules` синхронизируются между собой;
- уведомления хранятся в подколлекции `users/{uid}/notifications`, а чаты — в `chats/{chatId}/messages`;
- удаление коллекций или полей согласуется в PR перед применением в production.
